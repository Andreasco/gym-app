# Gym – personal workout PWA

Static web app for gym workout plans. No backend, no build step: it runs on GitHub Pages and installs on iPhone via Safari → *Share* → *Add to Home Screen*.

- **Exercises:** [free-exercise-db](https://github.com/yuhonas/free-exercise-db) (public domain, 876 exercises), bundled in `data/exercises.json`. Images are loaded from the upstream repo and cached offline by the service worker.
- **Storage:** `localStorage` on the device, optionally synced with a **private** GitHub repository (see below).
- **Plans:** JSON files (schema below), generated by Claude and imported via *Importa scheda*.

## Architecture

No framework, no build step: native ES modules loaded by the browser.

```
index.html, styles.css        layout shell and all styling (design tokens in :root)
js/main.js                    entry point: wires core events to the UI, boot, service worker
js/core/                      application logic — no DOM access
  config.js                   constants (app version, storage key, image base URL)
  i18n.js                     Italian labels for muscles, equipment, levels
  exercises.js                exercise catalog: load, lookup, search, image URLs
  store.js                    state + every mutation (actions); persists to localStorage, emits events
  queries.js                  read-only derived data: history, records, stats, plan lookup
  validate.js                 program schema validation
  sync.js                     GitHub REST client and two-way reconcile
  sync-service.js             runs sync, tracks status, emits events
js/ui/                        presentation — reads via core getters/queries, writes only via store actions
  dom.js                      DOM/format helpers, toast, share/download
  shell.js                    top bar, tab bar, <main> container
  router.js                   hash routes → views
  components.js               shared fragments (cards, chips, options) and the exercise picker
  timer.js                    rest timer bar
  views/*.js                  one module per screen
```

A visual redesign only touches `styles.css`, `index.html` and `js/ui/`; `js/core/` stays unchanged.

## Program schema (v1)

```json
{
  "schemaVersion": 1,
  "id": "optional-stable-id",
  "name": "Upper / Lower – Block 1",
  "description": "optional",
  "goal": "optional, e.g. Ipertrofia",
  "level": "beginner | intermediate | expert (optional)",
  "weeks": 8,
  "days": [
    {
      "id": "upper-a",
      "name": "Upper A",
      "notes": "optional, shown on top of the day",
      "exercises": [
        {
          "exerciseId": "Barbell_Bench_Press_-_Medium_Grip",
          "name": "optional custom display name, e.g. Panca piana",
          "sets": 4,
          "reps": "6-8",
          "restSec": 150,
          "rpe": 8,
          "weightKg": 60,
          "notes": "optional coaching cue"
        }
      ]
    }
  ]
}
```

| Field | Required | Notes |
|---|---|---|
| `name`, `days[].name` | yes | A program (scheda) is split into days (giorni) |
| `goal`, `level`, `weeks` | no | Shown as metadata on the home list |
| `days[].exercises[].exerciseId` | yes | Must be an `id` from `data/exercises.json` |
| `sets` | yes | Integer > 0 |
| `reps` | no | String: `"8"`, `"6-8"`, `"45s"` |
| `restSec` | no | Starts the rest timer when a set is ticked |
| `name` (exercise) | no | Custom display name; defaults to the database name |
| `rpe`, `weightKg`, `notes` | no | `weightKg` is the starting weight when there is no history |

## GitHub sync

*Dati → Sincronizzazione GitHub* links a private data repository using a
fine-grained personal access token scoped to that single repository with **Contents: Read and write** only.
The token is stored in `localStorage` on the device and sent only to `api.github.com` (enforced by the page CSP).

Repository layout:

```
programs/<id>.json                       one file per program (Claude adds/edits these)
sessions/<yyyy>/<yyyy-mm-dd>-<id>.json   one file per finished workout
```

Sync runs on app start, when the app returns to the foreground, after finishing a workout, importing or
deleting. Remote changes win for files already known locally; new local items are pushed; local deletions
delete the remote file.

## Backup format

*Esporta backup* produces `{ app, schemaVersion, exportedAt, programs[], sessions[], activeProgramId, activeSessionId }`.
Each session: `{ id, programId, dayId, dayName, startedAt, finishedAt, entries: [{ exerciseId, planId, name, note, sets: [{ weight, reps, done }] }] }`.
`planId` is the planned exercise when it was swapped during the workout (`null` for an exercise added on the fly); `note` is the user's note for that exercise in that workout.
Send this file to Claude to get the next plan adjusted to actual progress.
